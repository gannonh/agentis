# Local provider contracts and eligibility

Research for [KAT-3251](https://linear.app/kata-sh/issue/KAT-3251), retrieved and probed September 6, 2026. Select **Codex app-server over stdio** and **Cursor ACP v1 over stdio** for the two local implementation paths. Both completed real synthetic model turns and approved scratch commands. **The two-provider support gate remains BLOCKED**, principally by Cursor's unproven blocking question/plan flow and the required macOS and execution-boundary evidence. These selections do not authorize selectable stubs or public support claims.

Gannon Hall owns the support decision and is the accountable Agentis integration maintainer for both selections. OpenAI owns Codex upstream; Anysphere owns Cursor upstream. Those vendors do not own Agentis adapters, diagnostics, or conformance tests. Before release, Gannon must accept the recorded limitations and the implementation evidence. No outreach occurred.

## Why app-server is the Codex transport

| Required property | Direct app-server | Current ACP wrapper |
| --- | --- | --- |
| Ownership and version diagnosis | One upstream protocol and tested executable | Adapter release plus a ranged Codex dependency and ACP/extensions |
| Native account, quota and failure information | Direct typed account/rate-limit/error messages | Translation must preserve the information Agentis needs |
| Blocking input and recovery | Exercised native requests; explicit history pagination and interruption state | Existing implementation, but extension negotiation and replay translation add another conformance surface |
| Shared transport implementation | Requires a small Codex-specific module | Reuses an ACP client with Cursor |
| Maintenance cost accepted here | Maintain two local transports | Maintain shared transport plus provider and adapter differences |

Select direct stdio app-server. Sharing ACP framing does not remove provider-specific questions, permissions, credential policy, or history semantics. The current ACP adapter is a viable maintained alternative, not a stub, but it does not add a required workflow capability established by this research. Its existence also removes the need to build a new universal ACP wrapper inside Agentis. WebSocket transport is not selected; the docs label TCP WebSocket experimental and unsupported.

Codex's required structured input surface is experimental and requires `experimentalApi` plus the tested plan collaboration mode. Accept that explicit version-bound risk for feasibility only. This is not an Effect RC exception. If the field disappears or a capability is missing, fail setup/conformance and report the unsupported version. Do not silently switch transport, provider, credentials, or session.

## Process and configuration contract

Agentis should supervise one selected provider subprocess per owned connection, with a fixed working directory, explicit authentication mode, pinned executable identity, bounded lifetime, and continuously drained stdout/stderr. Both selected transports use newline-delimited messages over stdin/stdout; stderr is separate diagnostics. JSON-RPC request ids and provider session ids remain distinct from Agentis task/run ids.

The probe disables Codex hooks. Native Codex authentication still loads installed configuration and plugins, including MCP services. Cursor accepts a scratch working directory and clean environment, but the live initialization also reported global commands. These are observations of inherited configuration, not evidence of an enforcement boundary. Cursor's [configuration reference](https://prod.cursor.com/docs/cli/reference/configuration) documents native configuration; the ACP session's `mcpServers: []` is not an isolation switch. KAT-3252 must establish the actual user/configuration, filesystem, network, and native-tool boundary before tool execution ships.

Loading a provider session only restores provider context. Cursor replay changed the prior tool id to `replay-1-0`; Codex warned that full-history hydration is deprecated for paginated threads. Use Codex `excludeTurns: true` and page history in the implementation. Neither replay proves durable Agentis approvals, effect reconciliation, SSE reconnect, or orphan cleanup. Preserve uncertain outcomes and keep real-resource mutations disabled until recovery verification passes.

## Remaining support gates

1. **BLOCKED, Cursor structured input.** With CLI 2026.09.02-c22c1a3, ACP v1, empty client capabilities, plan mode, and the explicitly selected GPT-5.6 Sol model, the prompt returned ordinary text saying the question tool was unavailable. Exact requirement is a documented client capability/configuration and successful real `cursor/ask_question` plus `cursor/create_plan` response flow, including rejection/cancellation. A model's assertion alone does not prove provider absence. Do not replace it with plain-text question success.
2. **UNVERIFIED, both selected integrations.** macOS Apple silicon clean installation, packaged CLI/daemon workflow, actual workflow artifacts, attachment delivery, controlled MCP execution, concurrent providers, native isolation, lost approval recovery, and child-process stop require KAT-3242, KAT-3243, KAT-3247, and KAT-3252 evidence. These Linux research probes cannot satisfy those product gates.
3. **UNVERIFIED, billing attribution.** Confirm the actual Cursor account/key billing allocation and dashboard charge for a timestamped probe. Confirm Codex plan/workspace entitlement and limits on the intended deployment account. Protocol usage is not an invoice. Agentis should report missing usage as unknown.
4. **UNAVAILABLE, Claude subscription; UNVERIFIED, Claude API.** No written Anthropic approval was supplied. The documented API path resolves the eligible alternative, but a funded Anthropic API credential provisioned through the supported SDK environment and live workflow evidence would be required to select it. Do not use existing claude.ai credentials as a substitute.
5. **UNVERIFIED, runtime/platform support.** [Node/Effect pins](runtime.md) passed the disposable Linux type/runtime check. macOS packaging, SQLite, daemon lifecycle, and canonical product schema/API remain implementation work.

All eight research AC have evidence locations in this document, [probes](probes.md), [runtime pins](runtime.md), and the draft PR. AC 3's full supported-provider outcome remains blocked by the items above; the two selections are concrete research decisions. Keep the PR draft and the issue open.
